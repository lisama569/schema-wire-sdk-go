# schema-wire-sdk-go

由 IDL schema 驱动的**版本化二进制编解码 SDK**：编写一份声明字段版本区间的
schema，生成确定性的 Go 类型与 TLV 编解码代码；生成产物与运行时保证协议在
持续演进时新旧版本仍然互通。

- 纯标准库，无第三方依赖
- 生成代码只依赖本模块的 `wire` 运行时
- 旧版数据、新版数据都能解码；解码到的未知新增字段在重新编码时**逐字节保留**
- 「数据损坏」与「版本不兼容」是两类可区分的错误

## 目录结构

| 路径 | 说明 |
| --- | --- |
| `schema/` | schema 词法/语法解析、语义校验、可区分的失败类别 |
| `wire/` | 二进制原语（varint / TLV / 信封）、损坏与版本错误分类 |
| `codegen/` | 确定性 Go 代码生成（临时目录暂存 + 原子安装） |
| `cmd/schemagen/` | 命令行入口 |
| `examples/demo/`, `examples/evolv/` | additive 与字段编号复用两个示例 schema 及其签入的生成产物 |
| `integration/` | 跨版本互通、未知字段保留、损坏数据等端到端测试 |

## Schema 语法

行导向语法，`#` 之后为行注释：

```text
package <goPackageName>;     # 可选；缺省时取输出目录名
version <uint>;              # 当前 schema 版本，必须 >= 1；缺省为 1
compat additive | none;      # 兼容策略，缺省 additive

message <Name> {
    <fieldNumber>: <type> <name> [since=<v>[, until=<v>]];
    ...
}
```

- 字段编号在消息内标识一个字段，必须 `>= 1`。
- `since` 缺省为 `1`；`until` 缺省（不写）表示该字段一直活跃到最新版本。
  区间为闭区间：`[since, until]`。
- 支持的标量类型：`int32` `int64`（zigzag varint）、`uint32` `uint64`
  （uvarint）、`bool`（uvarint 0/1）、`float64`（fixed64 LE）、`string`、
  `bytes`（长度前缀），以及任意已声明的消息类型（嵌套，长度前缀）。
- 标识符遵循 Go 风格要求；`snake_case` 与 `camelCase` 会规范化为同一个
  稳定的导出 Go 名（`foo_bar` 与 `FooBar` 视为冲突）。
- 一行可以放多条 `;` 分隔的字段，也可以写单行 `message M { ... }`。

### 演进与兼容规则

`compat additive;`（默认，纯新增式演进）：

- 只允许新增字段；
- **字段编号永不复用**：即使两个同编号字段的活跃区间不重叠，也视为
  「移除/变更已有字段」，以 `compat_conflict` 拒绝；
- 旧字段不能带 `until`（移除），否则与 additive 承诺矛盾。

`compat none;`（不承诺兼容）：

- 允许字段退出（`until`）与编号复用，但同编号字段的活跃区间
  **必须互不重叠**，重叠以 `duplicate_field_number` 拒绝。

无论哪种策略，运行时都能读取历史上的所有版本：编号在哪个版本是什么类型，
由该字段编号在**报文自报版本**下的身份决定。

### 校验失败类别（可区分）

| Kind | 触发条件 |
| --- | --- |
| `syntax` | 无法解析的语句、畸形选项、非法标量类型 token |
| `duplicate_field_number` | 同编号字段在同一版本上有两个活跃身份（区间重叠） |
| `unknown_type` | 字段引用了不存在的标量或消息类型 |
| `invalid_version` | `version=0`、`since>until`、`since/until` 超出当前版本等 |
| `compat_conflict` | 演进声明与 `compat` 策略互相矛盾（additive 下移除/复用编号） |
| `invalid_name` | 非法标识符、与 Go 关键字冲突、导出 Go 名冲突 |
| `duplicate_declaration` | 同名消息、重复头部指令 |
| `empty_schema` | 空 schema、无消息、消息无字段 |
| `io_error` | 读取输入失败 |

**校验未通过时不会产出任何生成结果。**

## 二进制格式（TLV + 版本信封）

每条顶层报文：

```text
<envelope version: uvarint>        # >= 1
<field>*                          # 消息体
```

每个字段：

```text
tag   = (field_number << 3) | wire_type   # uvarint
value = 取决于 wire_type
```

wire type：

- `0` varint：`int32/int64`（zigzag）、`uint32/uint64`、`bool`
- `1` fixed64 LE：`float64`
- `2` 长度前缀：`string`、`bytes`、嵌套消息
- `5` fixed32：保留

## 生成流程

```bash
go run ./cmd/schemagen \
  -schema examples/demo/demo.schema \
  -out examples/demo/gen/demo \
  -package demo
```

产物（每个消息一个文件 + 一个描述符文件）：

- 结构体合并该消息在**全部版本**出现过的字段，全部为指针（`nil` 表示未出现）；
- `Marshal<Msg>(m, viewVersion)` / `Unmarshal<Msg>(b, m, knownVersion, strict)`；
- 字段按 `(编号, since)` 稳定排序，导出标识符稳定，gofmt 规范化；
- 同一份 schema 重复生成**逐字节一致**；
- 写入流程：渲染 → 冲突预检 → 写入输出目录下的**独占临时目录** → 逐个
  `rename` 安装；任何一步失败都清理暂存目录，目标目录不残留半成品；
  并发生成不同目标包使用不同临时目录，互不污染；
- 目标文件名若已存在且**不带** `// Code generated by schemagen; DO NOT EDIT.`
  头，拒绝覆盖（`output_conflict`），保护手写代码。

## 版本兼容与互通语义

解码时使用两个版本：

- **报文版本（wireVersion）**：信封里的版本，决定字段编号的身份与
  线缆类型（写入方视角）；
- **本地理解版本（knownVersion）**：调用方代码发布时的 schema 版本。
  编号在该版本尚不存在的字段作为未知原始记录保留；若按报文版本找不到字段
  身份（典型：新版字段经旧版二进制透传），回退按本地理解版本解释，使新
  代码仍能还原这些字段。

- `strict=true`：报文版本高于 `knownVersion` 直接返回
  `incompatible_version`；
- `strict=false`（默认）：前向兼容，未知字段保留。

重新编码（以某视图版本）时：目标版本下有活跃身份的编号由显式字段写出，
其余未知原始记录原样追加，保证不重复、不丢失。

### 运行时错误两类（可区分）

| 判定 | 说明 |
| --- | --- |
| `wire.KindCorrupt`（`wire.IsCorruption(err)`） | 截断、长度越界、非法/溢出 varint、未知 wire type、字段编号 0、线缆类型不符等 |
| `wire.KindIncompatibleVersion`（`wire.IsIncompatibleVersion(err)`） | 信封版本为 0、或 strict 模式下版本高于本地理解版本——数据结构完整但版本不被接受 |

## 本地验证

```bash
# 全部单元测试与跨版本端到端测试
go test ./...

# 竞态检测（覆盖并发生成）
go test -race ./codegen/...

# 重新生成示例（产物已签入，可用来验证确定性：生成后 git diff 应为空）
go run ./cmd/schemagen -schema examples/demo/demo.schema  -out examples/demo/gen/demo  -package demo
go run ./cmd/schemagen -schema examples/evolv/evolv.schema -out examples/evolv/gen/evolv -package evolv
git status --porcelain   # 期望无输出

go vet ./...
```

测试日志会打印每个用例的输入字节、判定依据与错误归类，例如损坏数据用例
打印 `输入=...；判定依据=...；错误归类=corrupt_data`。
